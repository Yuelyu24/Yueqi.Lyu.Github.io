From a URL to
a secure page.

Connecting the network layers to the protocols behind a personal website.

These are learning notes and testing instructions. They do not contain measured IP addresses, latency values or packet-capture results.

01 / A typical HTTPS connection over TCP

Four jobs behind one page.

01 / NAME

DNS

The client obtains address information for a hostname. A cached result can avoid a new visible DNS exchange.

02 / CONNECT

TCP

A new TCP connection normally begins with SYN, SYN-ACK and ACK. TCP supplies reliable, ordered byte delivery.

03 / PROTECT

TLS

The client and server establish protected communication. Certificate validation helps the browser authenticate the server.

04 / REQUEST

HTTP

The browser requests the document and its resources. HTTPS protects these HTTP messages in transit.

This is a simplified first-connection example. Connections can be reused. HTTP/3 uses QUIC over UDP, with TLS 1.3 integrated into QUIC, so a TCP handshake is not part of that connection. Record the protocol actually observed.

The five-layer model revisited

TLS is a security protocol above TCP in the HTTPS-over-TCP stack; it is not an additional layer in the five-layer teaching model.

02 / Security in practice

What protection means.

Confidentiality

Encryption protects message contents from an observer who does not have the required secrets. A normal HTTPS capture does not expose the page body as readable HTTP.

Authentication

The browser checks the server's certificate and hostname. A valid certificate identifies the endpoint for that name; it does not certify that the page's claims are true.

Integrity

Cryptographic protection detects tampering with protected messages. An ordinary transport checksum is not a cryptographic authenticity guarantee.

Availability

A service must remain reachable to be useful. Encryption alone cannot guarantee availability or prevent every denial-of-service attack.

Week 6 also introduces signatures, certificate authorities, IPsec and firewall filtering. The most direct connection to this website is HTTPS and TLS.

The command-line tools run on your computer. This static page does not send ICMP ping probes or perform traceroute from the browser.

What should a DNS result tell me?

Distinguish the resolver's address from the website's returned addresses. Record any A and AAAA answers, the query time and the address the browser actually used. Shared hosting can return several addresses, and a later answer can differ.

What does a ping time measure?

It is a round-trip observation for an ICMP Echo exchange, not the full page-load time. Report sent and received counts, loss and available RTT statistics. If all probes time out, report the timeout; it does not by itself prove that HTTPS is unavailable.

How should I interpret traceroute?

It probes with increasing TTL or Hop Limit to reveal responding hops. An asterisk means no response arrived within that probe's wait period. Filtering, rate limits and routing changes can make the observed route incomplete.

What should I look for in Wireshark?

Start the capture before opening the site. Use the active interface, identify the server address and inspect the relevant stream. For a TCP-based HTTPS session, look for the handshake and TLS traffic. HTTP/3 may appear as QUIC over UDP instead. Browser developer tools can show HTTP request details that are encrypted in the packet capture.

04 / A connection to streaming research

Networks also shape
video quality.

Week 6 discusses DASH: a video is divided into segments, and the client selects representations as conditions change. Adaptive bitrate decisions balance visual quality, stalls and changes in quality.

The lecture introduces Pensieve as a learning-based approach to adaptive bitrate selection, and DAVE as work on dynamic encoding for real-time video. This website is a static portfolio; it does not implement either streaming system.
